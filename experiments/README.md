# Эксперименты

Восемь экспериментов: вызов инструментов, ведение плана и управление контекстом. Они собраны в три группы. Для каждого указаны стадии агента и результат, который нужно наблюдать.

В каталоге лежат задания, скрипты и синтетические данные. README описывают ожидаемое поведение и условия проверки.

## Инструменты и ограничения · Bootstrap → M1

| Эксперимент                                                     | Стадии                               | Что наблюдать                                                   |
| --------------------------------------------------------------- | ------------------------------------ | --------------------------------------------------------------- |
| [Незавершающаяся команда](tools/bash-budget/README.md)          | `stage-bootstrap`                    | Bash ждёт завершения команды, цикл агента не получает результат |
| [Prompt injection](tools/bash-injection/README.md)              | `stage-bootstrap`                    | Выполнит ли агент лишний локальный POST после чтения HTML       |
| [Выход за рабочую директорию](tools/workspace-escape/README.md) | `stage-bootstrap` → `stage-m1-tools` | Bash читает соседний файл; `read_file` отклоняет тот же путь    |
| [Большой файл](tools/large-file/README.md)                      | `stage-bootstrap` → `stage-m1-tools` | Полный результат Bash и усечённый результат `read_file`         |

`bash-budget` и `bash-injection` показывают проблему; варианты с защитой не реализованы. В агенте нет таймаута, ограничения объёма Bash-вывода и специализированного `get_release_info`. Проверка пути в M1 ограничивает файловые инструменты; через Bash по-прежнему можно обратиться к соседнему файлу.

## Управление контекстом · M3 → M4a → M4b

| Эксперимент                                                  | Стадии                                               | Что наблюдать                                               |
| ------------------------------------------------------------ | ---------------------------------------------------- | ----------------------------------------------------------- |
| [Переполнение контекста](context/context-overflow/README.md) | `stage-m4a-micro-compact`                            | Большой свежий результат может превысить лимит входа модели |
| [Micro-compact](context/micro-compact/README.md)             | `stage-m3-subagents` → `stage-m4a-micro-compact`     | Замена старых больших результатов короткими маркерами       |
| [Auto-compact](context/auto-compact/README.md)               | `stage-m4a-micro-compact` → `stage-m4b-auto-compact` | Замена истории кратким пересказом и продолжение задачи      |

Auto-compact использует тот же [большой лог](tools/large-file/README.md), что и эксперимент с файловым инструментом. Слишком большой результат может превысить лимит и в запросе на сжатие истории.

Отдельных экспериментов для субагентов (M3), skills (M5) и проверки результата (M6) здесь пока нет. В сравнении micro-compact стадия M3 служит исходным вариантом.

## Как запустить нужную стадию

Начните с [требований и настройки API](../README.md#требования) в корневом README. Для локальных HTTP-серверов и генератора большого вывода также нужен Python 3; для prompt injection — curl.

В тегах `stage-*` ещё нет этих экспериментов. Оставьте репозиторий на `main`, а исходники нужной стадии извлеките во временный каталог. Из корня репозитория выполните:

```bash
DEMO_STAGE=stage-m1-tools
DEMO_AGENT_SOURCE="$(mktemp -d /tmp/podlodka-agent.XXXXXX)"
git archive "$DEMO_STAGE" | tar -x -C "$DEMO_AGENT_SOURCE"
swift build --package-path "$DEMO_AGENT_SOURCE"
DEMO_AGENT_BIN="$(swift build --package-path "$DEMO_AGENT_SOURCE" --show-bin-path)/agent"
```

В `DEMO_STAGE` укажите тег из таблицы. После успешной сборки в том же терминале запустите `"$DEMO_AGENT_BIN"` и введите запрос из README эксперимента. Относительные пути в заданиях рассчитаны на запуск из корня репозитория с материалами. У `workspace-escape` и `bash-injection` свои рабочие каталоги — следуйте их инструкциям после сборки.

Для второго варианта сравнения повторите сборку с другим тегом. Каждый запуск начинайте в новом процессе: история сохраняется между запросами REPL. Текущий `main` содержит все механизмы и может менять условия ранних экспериментов.
