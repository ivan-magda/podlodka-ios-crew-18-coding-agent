# M1: Tools / Guardrails

Продолжи текущий Bootstrap. Оставь Bash без ограничений. Добавь специализированные инструменты `read_file`, `write_file` и `edit_file`.

## Структура

- Создай один экземпляр `FileTools`.
- Вычисли его `root` из рабочей директории через `standardizedFileURL.resolvingSymlinksInPath()`.
- Добавь в `FileTools` методы `readFile`, `writeFile` и `editFile`. Каждый метод принимает JSON arguments как `String`.
- Размести эти методы, закрытые типы аргументов и строгие JSON Schemas в `FileTools.swift`.
- Предоставь схемы через `static let definitions`.
- Сопоставь `old_text` и `new_text` со Swift properties через `CodingKeys`.
- Добавь в `Bash.swift` метод `execute(_ arguments: String)` и `static let definition`.
- `Bash.execute` печатает `$ <command>` ровно один раз, но не печатает полный результат команды.
- Передавай модели `[Bash.definition] + FileTools.definitions`.

В `Agent.executeTool`:

- Создай локальный словарь `[String: (String) async throws -> String]`.
- Используй значения `bash.execute`, `fileTools.readFile`, `fileTools.writeFile` и `fileTools.editFile`.
- Не заменяй словарь на `switch`.
- Не храни словарь обработчиков в свойстве `Agent`.
- Не используй фабрики, `merging` и стирание типов для dispatch.
- Не оставляй JSON Schemas и schema helpers в `Agent.swift`.

## Ограничения файлов

- Принимай только относительные пути внутри рабочей директории.
- Отклоняй абсолютные пути.
- Получи целевой URL как `root.appendingPathComponent(path).standardizedFileURL`.
- Разрешай URL, только если его путь равен `root.path` или начинается с `root.path + "/"`.
- Проверяй символические ссылки от `root` до целевого пути.
- При проверке обходи `file.pathComponents.dropFirst(root.pathComponents.count)`.
- Для каждого компонента напрямую вызывай `FileManager.destinationOfSymbolicLink`. Не проверяй перед этим `fileExists`.
- Не используй `Darwin` и `lstat`.
- Если `destinationOfSymbolicLink` успешно вернул значение для компонента, сразу отклони путь. Положение target не имеет значения.
- `read_file` читает UTF-8. Если результат длиннее 50 000 символов, обрежь его и добавь маркер.
- `write_file` создаёт родительские директории и атомарно записывает строку.
- `edit_file` принимает непустой `old_text`. Атомарно замени его, только если он встречается ровно один раз.

Для ошибок используй один простой `LocalizedError` с текстом.

## Результаты инструментов

- Перед вызовом обработчика напечатай `→ <имя инструмента>`.
- Если обработчик завершился ошибкой или имя неизвестно, преобразуй ошибку в строку результата.
- Напечатай строку ошибки и верни её модели как связанный результат инструмента.
- Не завершай цикл агента после ошибки инструмента.
- Передавай модели полный результат обработчика.
- Для любой возвращаемой строки, включая ошибку, показывай в консоли имя инструмента, первые 200 символов и отметку об обрезке.
- В системном промпте попроси модель предпочитать файловые инструменты.
- Не называй файловые инструменты общей гарантией изоляции.

## Ограничения

- Код будут читать на слайдах. Используй отступ в два пробела и многострочное форматирование.
- Не используй точки с запятой, однострочные блоки, длинные инициализаторы и JSON-схемы в одной строке.
- Не добавляй `list_directory`, протоколы, реестр, тесты и механизмы следующих стадий.
- Не изменяй `README.md` и `prompts/`. Не создавай Git-коммит.
