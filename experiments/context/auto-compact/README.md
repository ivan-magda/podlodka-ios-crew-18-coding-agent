# Auto-compact: сжать историю и продолжить задачу

Агент читает [лог](../../tools/large-file/runtime.log) на 120 000 ASCII-символов, сжимает историю и продолжает задачу. Лог уже лежит в репозитории.

Сравнение: `stage-m4a-micro-compact` → `stage-m4b-auto-compact`. Соберите M4b по [общей инструкции](../../README.md#как-запустить-нужную-стадию), запустите `"$DEMO_AGENT_BIN"` из корня репозитория и вставьте одну строку:

```text
Прочитай experiments/context/auto-compact/prompt.md и выполни описанное в нём задание.
```

Ожидаемая последовательность:

1. Bash выполняет `cat` и возвращает полный лог в историю основного агента.
2. В начале следующей итерации сериализованная история превышает демонстрационный порог 100 000 символов.
3. Отдельный запрос без инструментов создаёт краткий пересказ истории — summary. После успешного непустого ответа прежняя история заменяется двумя сообщениями: исходным системным и пользовательским с summary, текущим Todo и просьбой продолжить.
4. Основной цикл возобновляет работу. Агент должен создать `report.md` в этой папке.

В отчёте должны быть описание диагностических строк и маркеры `BEGIN_LARGE_FILE` и `END_LARGE_FILE`; текст — по-русски и не длиннее пяти строк. Summary может потерять детали. Если агент перечитает файл, чтобы восстановить их, зафиксируйте это в записи запуска.

Чтобы показать само сжатие, проверьте размер истории до и после и её замену в `messages`. Можно добавить диагностический вывод; в материалах эксперимента его нет. Одного готового отчёта недостаточно.

`cat` возвращает достаточно текста, чтобы пересечь порог сжатия. `read_file` ограничивает результат 50 000 символов и не вернёт тот же объём за один вызов. Фильтрация через `head` или `tail` тоже меняет эксперимент. Проверяйте фактическую команду.

Micro-compact сохраняет свежий результат целиком. На M4b в начале следующей итерации auto-compact проверяет размер истории, поэтому полный лог попадает в запрос на summary.

Для сравнения выполните тот же запрос на стадии M4a: один свежий большой результат остаётся полным, отдельного запроса на summary нет. Каждый вариант начинайте в новом процессе агента. Перед повтором уберите предыдущий `report.md`, чтобы исходное состояние совпадало.
